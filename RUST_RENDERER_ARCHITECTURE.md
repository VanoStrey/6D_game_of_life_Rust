# Rust 3D Renderer & UI Architecture: 6D Game of Life

Настоящий документ описывает архитектуру графической подсистемы, модель инстансинга на GPU, реализацию свободной камеры, синхронизацию симуляции с рендерингом и пользовательский интерфейс проекта **6D Game of Life** на стеке **wgpu 30 + winit 0.30 + egui 0.36**.

## 1. Архитектурный обзор графической подсистемы

Графическая подсистема спроектирована по принципу строгой изоляции слоев:

```text
               ┌───────────────────────┐
               │    Simulation Core    │  (Linear ByteGrid, Rayon)
               └───────────┬───────────┘
                           │ collect_alive_positions(&Grid, delta)
                           ▼
               ┌───────────────────────┐
               │   Projection Module   │  (ND -> 3D Coordinate Mapping)
               └───────────┬───────────┘
                           │ create_instances_from_positions()
                           ▼
               ┌───────────────────────┐
               │    GPU State & Pipe   │  (wgpu 30 Instanced Draw Call)
               └───────────┬───────────┘
                           │
       ┌───────────────────┴───────────────────┐
       ▼                                       ▼
┌──────────────┐                       ┌──────────────┐
│  Camera 3D   │                       │   egui UI    │
│ (World WASD) │                       │ (Params & OS)│
└──────────────┘                       └──────────────┘
```

Ни один модуль рендерера не содержит бизнес-логики или правил клеточного автомата.

## 2. Instanced Rendering и GPU Pipeline

### 2.1. Преодоление ограничений JavaFX 3D
В оригинальной JavaFX-версии для каждой возможной точки пространства создавался отдельный объект `javafx.scene.shape.Box`. Для конфигурации 6D ($54 \times 54 \times 54$) создавалось **$157\,464$ независимых нод в графе сцены**, что вызывало катастрофические просадки FPS (< 1-2 FPS).

В реализации Rust на `wgpu`:
1. **Единая разделяемая геометрия куба (Shared Mesh)**:
   - Размер ребра: $100.0$ единиц (half-size $50.0$, от $-50$ до $+50$), что в точности соответствует размеру `cubeSize = 100` в Java.
   - 24 вершины (по 4 на каждую из 6 граней с жесткими нормалями) и 36 индексов (12 треугольников).
2. **Instance Buffer**:
   - Каждый инстанс представляет собой структуру `InstanceRaw` (16 байт):
     ```rust
     #[repr(C)]
     #[derive(Copy, Clone, Pod, Zeroable)]
     pub struct InstanceRaw {
         pub position: [f32; 3], // Мировые координаты куба
         pub _pad0: f32,
         pub color: [f32; 3],    // Цвет JavaFX Color.DARKBLUE [0.0, 0.0, 0.545]
         pub _pad1: f32,
     }
     ```
   - Буфер содержит **только живые клетки**, проецируемые из симуляции. Мертвые клетки не занимают памяти в GPU и не отрисовываются.
   - Отрисовка всех десятков тысяч кубов выполняется **за ровно один вызов `draw_indexed`**:
     ```rust
     render_pass.draw_indexed(0..gpu.num_indices, 0, 0..gpu.instance_count);
     ```

### 2.2. Шейдерная модель (`shader.wgsl`)
- Освещение: двухточечная модель Lambert/Blinn-Phong с рассеянным светом (diffuse) и фоновой составляющей (ambient = 0.35) для четкого восприятия трехмерной формы и ребер каждого кубика.
- Цвет: оригинальный темно-синий `Color.DARKBLUE` (`vec3<f32>(0.0, 0.0, 0.545)`).

## 3. Модель камеры и управление (Unity Editor Fly-Camera)

Камера в [src/renderer/camera.rs](file:///Users/foolvan/Desktop/6D_game_of_life_Rust/src/renderer/camera.rs) работает по принципу свободного полета (Fly-Camera), аналогично редактору Unity:

| Параметр | Значение в Rust |
| :--- | :--- |
| **Начальная позиция** | `Vec3::new(1000.0, 5500.0, -2500.0)` |
| **Начальный Pitch (X)** | `rotation_x = 53.0` |
| **Начальный Yaw (Y)** | `rotation_y = 0.0` |
| **Скорость движения** | `speed_movement = 20.0` |
| **Чувствительность мыши** | `speed_rotation = 0.05` |
| **Дальняя плоскость отсечения** | `z_far = 50000.0` |

### Принцип перемещения (Relative View Space Translation)
Перемещение клавишами выполняется **относительно направления взгляда камеры** (локальные оси Forward, Right, Up):
- `W`: Вперед (в сторону взгляда камеры, vector $\vec{F}$)
- `S`: Назад (против вектора взгляда, $-\vec{F}$)
- `A`: Влево (стрейф влево, $-\vec{R}$)
- `D`: Вправо (стрейф вправо, $+\vec{R}$)
- `Space` / `E`: Вверх относительно взгляда камеры ($+\vec{U}$)
- `Shift` / `Q`: Вниз относительно взгляда камеры ($-\vec{U}$)

Вращение осуществляется зажатием левой (ЛКМ) или правой (ПКМ) кнопки мыши и перемещением курсора:
- Перемещение мыши вверх/вниз наклоняет камеру вверх/вниз с ограничением Pitch $[-89.5^\circ, +89.5^\circ]$.
- Перемещение мыши влево/вправо поворачивает камеру (Yaw).

## 4. Слой пользовательского ввода (Input State)

Ввод изолирован от рендерера в [src/input/input_state.rs](file:///Users/foolvan/Desktop/6D_game_of_life_Rust/src/input/input_state.rs):
- Оконные события `winit::event::WindowEvent` обновляют `InputState`.
- `egui` перехватывает клики и ввод, если курсор находится над окном интерфейса (`consumed = true`), предотвращая случайное вращение камеры при взаимодействии с элементами UI.
- Логичные горячие клавиши симуляции:
  - `P` — Пуск / Пауза непрерывной симуляции;
  - `Enter` / `N` — Одиночный шаг симуляции (Next step);
  - `R` — Случайное перераспределение клеток (Randomize);
  - `C` / `Home` — Сброс камеры в начальное положение обзора;
  - `1` .. `6` — Мгновенное переключение размерности (1D–6D);
  - `T` — Сброс размерности в 1D (legacy).

## 5. Графический интерфейс на egui

Панель управления [src/ui/app_ui.rs](file:///Users/foolvan/Desktop/6D_game_of_life_Rust/src/ui/app_ui.rs) предоставляет:
1. **Режимы выполнения**:
   - `Step` — одиночный шаг;
   - `Play / Pause` — непрерывный запуск поколений с регулировкой скорости от 0.5 до 60 шагов/сек;
   - `Randomize` — заполнение случайными клетками (50%).
2. **Настройки параметров гиперрешетки**:
   - Слайдер мерности $D \in [1, 6]$;
   - Слайдер размера ребра $\text{size} \in [1, 12]$;
   - Слайдер зазора $\Delta \in [0, 8]$;
   - Слайдеры процентных порогов `min%` и `max%` ($0..100\%$).
3. **Статистика в реальном времени**:
   - Номер поколения;
   - Количество живых клеток и процент заполнения;
   - Количество GPU-инстансов;
   - Габариты визуальной сетки $X \times Y \times Z$;
   - Время шага симуляции CPU (мс);
   - Частота кадров рендерера (FPS).

## 6. Синхронизация симуляции и рендеринга

В главном цикле `ApplicationHandler` ([src/app.rs](file:///Users/foolvan/Desktop/6D_game_of_life_Rust/src/app.rs)) жестко разделены фазы:
1. **Фаза обновления симуляции**: При нажатии `Step` или по таймеру `Play` вызывается `simulation.step()`.
2. **Фаза сбора позиций**: Вызывается `collect_alive_positions(&current, delta)` и формируется вектор `InstanceRaw`.
3. **Фаза обновления GPU-буфера**: `queue.write_buffer` отправляет только компактный массив позиций живых клеток. Если число живых клеток превышает текущую емкость буфера, буфер динамически расширяется с удвоением емкости (`next_power_of_two`).
4. **Фаза Render Pass**: В едином проходе рендеринга отрисовываются все 3D-инстансы кубов и поверх них накладывается интерфейс `egui`.

## 7. Безопасное переключение размерности (1D $\leftrightarrow$ 6D)

В Java нажатие клавиши `T` приводило к `ArrayIndexOutOfBoundsException` из-за попытки обратиться к 3D-массиву устаревшего размера.

В Rust метод `reconfigure_simulation()` выполняет атомную реконфигурацию:
```rust
let rules = Rules::new(self.ui_config.percent_min, self.ui_config.percent_max);
self.simulation = Simulation::new(self.ui_config.size, self.ui_config.dimensions, rules);
self.simulation.randomize(&mut self.rng);
self.rebuild_instances();
```
Все переходы `1D → 2D → 3D → 4D → 5D → 6D → 1D` протестированы автоматическим тестом `test_dimension_switching_cycle_no_panic` и работают гарантированно стабильно.

## 8. Таблица сопоставления: JavaFX $\to$ Rust / wgpu

| Компонент JavaFX | Компонент Rust / wgpu | Отличия и преимущества Rust |
| :--- | :--- | :--- |
| `javafx.scene.shape.Box` (отдельный объект на каждый куб) | `renderer::mesh::Vertex` + `InstanceRaw` | 1 общий куб на весь GPU, 1 draw call для всех живых клеток |
| `CubeVisibilityHandler.updateCubesVisibility` | `InstanceBuffer` update | Мертвые клетки не занимают память GPU; нет оверхеда на невидимые ноды |
| `PerspectiveCamera(true)` | `renderer::Camera` + `CameraUniform` | Идентичная математика и World Space WASDQE, но вычисляется напрямую через `glam::Mat4` |
| `CameraTransform` Mouse Drag | `InputState` + mouse delta | Плавный трекинг без захвата UI |
| JavaFX `GridPane` окно настроек | `egui` окно управления | Слайдеры с валидацией, смена параметров на лету без перезапуска окна, Play/Pause |
| `sizes[2], sizes[1], sizes[0]` | `VisualBounds::compute` | Идентичные габариты $X = d + c(\text{size}+\Delta), Y = e + b(\text{size}+\Delta), Z = f + a(\text{size}+\Delta)$ |
| Stop-The-World GC паузы | Zero-allocation render loop | 0 байт аллокаций в кадре, стабильные 60 FPS |

## 10. Визуализация гиперкоординат (Hyperdimension Color Mapping)

Для подробного описания модели цветового кодирования многомерного пространства см. отдельный документ [RUST_HYPERDIMENSION_VISUALIZATION.md](file:///Users/foolvan/Desktop/6D_game_of_life_Rust/RUST_HYPERDIMENSION_VISUALIZATION.md).

Основные свойства:
* **Presentation Layer**: вычисление цветов вынесено в `src/renderer/color.rs` и не затрагивает ядро симуляции.
* **$O(1)$ Обращение проекции**: координаты $(a, b, c)$ восстанавливаются из сжатых 3D-координат без клонирования сетки и без динамических аллокаций.
* **Режимы**: `ColorMode::Hyperdimension` (хроматическое кодирование 4D/5D/6D срезов) и `ColorMode::Uniform` (классический темно-синий цвет).
* **GPU Instancing**: сохранен ровно 1 draw call для всей сцены.
